# ComplyOn LLC — Marketing Site

The single-page marketing site for ComplyOn LLC, an independent compliance
and risk advisory practice. It is a static page: one hand-written HTML file
with inline CSS and no JavaScript framework.

## Requirements

- Node.js 20.19+ (developed on v22)
- npm

## Getting started

```bash
npm install
npm run dev
```

The dev server prints a local URL (http://localhost:3001, set in
`vite.config.js`) and reloads the page whenever you save.

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Start the Vite dev server with live reload. |
| `npm run build` | Build a static site into `dist/`. |
| `npm run preview` | Serve the built `dist/` locally to check it before deploying. |
| `npm run lighthouse` | Build, then audit the output with Lighthouse CI. |

## Layout

```
index.html        the entire site — markup, CSS and script in one file
reema-keen.jpg    founder portrait, referenced from the About section
fonts/            self-hosted woff2 subsets (see Fonts below)
vite.config.js    dev server port and build output settings
dist/             build output (generated, git-ignored)
```

**Edit `index.html` at the project root, not `dist/index.html`.** Everything
in `dist/` is regenerated by `npm run build` and any edits there are lost.

## How the page is organised

All CSS lives in one `<style>` block in the document head, grouped by
section with comment headers (`/* ---------- nav ---------- */` and so on).
The markup below it follows the same order: nav, hero, stats, about, quote
band, services, who we serve, track record, engagements, FAQ, contact,
footer.

The favicon is an inline SVG data URI in the head — there is no icon file.

## Fonts

Newsreader (the serif) and Inter (the sans) are **self-hosted** from
`fonts/`. The page makes no third-party request to render, which removes a
render-blocking round trip to `fonts.googleapis.com` and avoids sending
visitor IP addresses to Google — the practice German courts have found to
breach GDPR.

The files come from the `@fontsource/*` packages, kept as devDependencies so
the origin is traceable and updates are a reinstall away. They are not
imported at build time; the `.woff2` files were copied into `fonts/` and are
committed, because GitHub Pages serves this repo's root and never runs the
build.

Only what the stylesheet asks for is shipped — Newsreader 200/300/400, Inter
300/400/500, latin subset, woff2 only — six files totalling ~140 kB. To add
a weight: copy the matching file out of `node_modules/@fontsource/<family>/
files/`, then add an `@font-face` rule in the stylesheet.

The two faces used above the fold (Newsreader 200 for the headline, Inter
400 for body text) are preloaded in the head; the rest load from the
`@font-face` rules. All six declare `font-display: swap`, so text paints
immediately in the fallback face rather than staying invisible.

## Responsive design

The base CSS is the desktop layout; every media query is a `max-width`
override that adapts it downward. Type and spacing are fluid (`clamp()`), so
the breakpoints only have to handle the column counts — each grid drops a
column at the width where its narrowest cell stops reading well, rather than
all of them at one shared number:

| Breakpoint | What changes |
| --- | --- |
| 1100px | Services go from three columns to two |
| 1000px | Engagements go to two columns; the third card spans the row |
| 980px | Hero body, about, section headers and contact stack; stats go to two columns; expertise grid halves |
| 900px | The nav collapses into the menu button |
| 720px | Services, stats and engagements go to one column; client rows and track-record entries stack; the form's name fields stack |
| 460px | Hero buttons go full width; the expertise grid goes to one column |
| 360px | The tagline under the wordmark is dropped |

Anchor offsets come from one variable: `--nav-h` (86px, 74px below 900px).
The sticky header height, the top of the mobile menu panel and the
`scroll-margin-top` that keeps a jumped-to section clear of the header all
read from it, so changing the header height is a one-line change.

### The header

The nav carries six destinations, which stop fitting beside the wordmark at
around 900px. Below that the links collapse into a drop-down panel opened by
the menu button; the panel closes on link click, on Escape, and on a resize
back to the desktop layout.

The collapsed styles are gated behind a `js` class that the script adds to
`<html>`. Without JavaScript the class never appears, the menu button stays
hidden, and the full set of links renders as a wrapped row — so a failed
script can never leave a visitor with a button that opens nothing. The
scroll reveal is gated the same way, so nothing can be stranded at opacity
0.

## Deployment

`npm run build` produces a self-contained `dist/` directory that any static
host will serve — no server-side runtime required. The build inlines nothing
new; it rewrites the image reference to a content-hashed filename in
`dist/assets/` so it can be cached aggressively.

## Contact form

The form posts to Formspree. Until an endpoint is configured, `action` holds
the placeholder `https://formspree.io/f/YOUR_FORM_ID` and the script detects
it and hands the filled-in fields to the visitor's email client via
`mailto:` instead. Replace `YOUR_FORM_ID` with the real form ID and the
`fetch` path takes over — no other change needed. Client-side validation and
a honeypot field (`_gotcha`) run either way.

## Lighthouse CI

`npm run lighthouse` builds the site and runs Lighthouse against `dist/`
three times, reporting the median. Configuration is in `lighthouserc.json`;
HTML and JSON reports land in `.lighthouseci/` (git-ignored) — open the
`.report.html` file for the full breakdown.

Scores for the current design (mobile form factor):

| Category | Score |
| --- | --- |
| Performance | 100 |
| Accessibility | 100 |
| Best Practices | 100 |
| SEO | 100 |

The thresholds in `lighthouserc.json` are set below that, so the run passes
today and fails on a regression.

### Known issues the audit reports

1. **`modern-image-formats` / `uses-responsive-images`** — the founder photo
   is a 936×1245 JPEG displayed at roughly a third of that. A WebP or AVIF
   at display size saves about 85 kB.
2. **`unminified-css`** — expected; nothing minifies the inline CSS yet.

Both are set to `warn`, so they appear in the output without failing the
run.
